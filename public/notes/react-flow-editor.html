A React node editor without a graph library

Pointer capture, responsive graph layout, keyboard controls and SVG edges

By Santhosh Vishal · 2026-11-12 · 6 min read

A node editor is a surprisingly effective portfolio test. Instead of reading a checklist of UI skills, someone can grab a node, draw a connection, use the keyboard, reset the graph and see how it responds on a phone. This article explains the lightweight interactive graph demo on my portfolio. It is an illustrative workflow editor, not a replacement for production graph frameworks.

Start with state, not the canvas

In FlowCanvas.tsx, nodes have stable IDs, labels, kinds and positions; edges store a source and target ID. React renders absolutely positioned node elements and an SVG layer for Bezier connectors. The demo starts with five nodes and four edges, uses controlled state, and refuses self-links and duplicate directed links.

interface GraphNode {
  id: string; label: string; kind: Kind;
  x: number; y: number;
}
interface GraphEdge { id: string; from: string; to: string; }

Pointer capture makes dragging reliable

On primary-button pointerdown, record the cursor-to-node offset and call setPointerCapture(pointerId). During pointermove, calculate local coordinates against the editor container and clamp the node to the available width and height. Pointer capture means dragging can continue even when the cursor temporarily leaves the node element. Do not animate left or top during an active drag; it creates lag between the finger/cursor and node.

A width-aware layout beats clipping

The layout helper computes how many node columns fit rather than forcing every workflow step into one long row. It sorts by an approximate depth before assigning grid slots. The canvas reserves enough height for the wrapped rows and remeasures width using ResizeObserver. It also remembers manual placement, avoiding an unsolicited layout reset when the container changes size.

const columns = Math.max(1,
  Math.floor((width - 2 * PAD + GAP_X) / (NODE_W + GAP_X)));
const height = Math.max(380,
  PAD * 2 + Math.ceil(nodeCount / columns) * (NODE_H + GAP_Y));

Keyboard behavior is a first-class interaction

Nodes accept focus. Arrow keys nudge a node by eight pixels, or by 24 while holding Shift. Input/output port actions support keyboard-only edge creation; focusable edges can be removed without a mouse. Use visible focus states and accessible descriptions, then test both wide and narrow viewports. A visual editor that works only with a pointer is incomplete.

Where this deliberately stops

The portfolio demo does not implement DAG cycle prevention, graph persistence, collaboration, automatic routing around obstacles, undo/redo or a production execution engine. A real product must handle those separately, and may benefit from ReteJS, React Flow, ELK or other mature solutions depending on constraints.

Try it: Open the live graph. Inspect: the layout helper and regression tests.
