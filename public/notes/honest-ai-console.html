A transparent AI-console simulation without API keys

Why lexical retrieval is useful for a portfolio—and why it is not RAG

By Santhosh Vishal · 2026-11-12 · 4 min read

A developer portfolio can demonstrate an AI-like conversational interface without paying for a hosted model or exposing an API key. But it must not imply that fake traces are real inference. This site contains an interactive local console built over a curated list of résumé and project facts; it deliberately avoids sending visitor prompts to a server.

What actually runs

The console normalizes queries, removes conversational fillers, tokenizes words, then scores documents against hand-authored keyword lists. Stronger phrase matches receive more weight than partial token matches. A small ranked set of source identifiers accompanies the selected answer. The reply itself is a curated text response, revealed progressively in the UI.

const ranked = agentDocs
  .map(doc => ({
    doc,
    score: keywordScore(query, tokens, doc.keywords),
  }))
  .sort((a, b) => b.score - a.score);

What does not run

There is no embedding API, vector database, cosine similarity, LLM generation, tool execution, or external prompt request. The trace steps are illustrative; their timings and normalized relevance badges are not network latency measurements or vector similarity values. This distinction matters when a portfolio is used as evidence of practical engineering ability.

What the demo can still prove

It demonstrates streaming-style progressive disclosure, a controllable stop action, query selection, curated citations, accessible form controls, interaction feedback, local state handling, and a UI that respects reduced-motion settings. The design can be explored without an API key and without collecting prompts.

What a real system would need

To replace the simulation with actual retrieval-augmented generation, use a server-side provider gateway, authenticated and authorized retrieval, validated tool schemas, secret management, request timeouts, evaluation fixtures and abuse limits. Never put a private model API key in a Vite frontend. Tools that can modify records need explicit permission boundaries and human approval for sensitive actions.

Try it: Ask the local demo about a project. Inspect: the lexical retrieval code and its interface.
