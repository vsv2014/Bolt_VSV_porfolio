## Google Search Console — owner verification required

Google must confirm site ownership through the signed-in Google account. Adding a token generated by another account does not grant the intended person access.

1. Go to https://search.google.com/search-console and add the **URL-prefix property** `https://santhoshvishal.vercel.app/`. Do **not** use a Domain property for `vercel.app`, which is not your registered domain.
2. Choose the **HTML tag** verification method (or HTML file upload), copy the exact Google-provided token/file, and deploy it through this repository. Do not add fake placeholder tokens or share Google passwords.
3. After clicking **Verify** in Search Console, open **Sitemaps** and submit `sitemap.xml`. The robots file already advertises this URL.
4. Use **URL Inspection → Request indexing** for the homepage and three individual engineering notes.
5. Review the **Page indexing**, **Search results → Performance**, and **Core Web Vitals** reports after Google begins collecting data. Google does not guarantee indexing or rankings and reports can lag.
6. Optional: connect a Search Console analytics app in ChatGPT when Search Console is verified, to inspect impressions, clicks and discovery queries without repeatedly exporting data.

## Publish technical lessons, not generic announcements

Do not post all three on the same day. Publish the best first, answer technical comments with code references, then distribute a different lesson a few days later. Never buy stars, trade stars, solicit spammy comments, or present sample data as customer metrics.

### Post A — React / SVG node editor

**Hook:** I built a small interactive node editor with React and SVG—without installing a graph framework.

**Body:** The interesting parts weren't drawing rectangles. They were pointer capture, preventing drag lag, width-aware auto-layout on mobile, focusable ports/edges, and making keyboard nudging feel deliberate. I broke down the decisions and trade-offs, including the features this *doesn't* implement (undo/redo, graph persistence, DAG validation or multi-user editing).

**Link:** https://santhoshvishal.vercel.app/notes/react-flow-editor.html

**Where:** LinkedIn; DEV Community (use the original URL as the canonical), a relevant frontend discussion if the post is genuinely useful. Invite feedback about keyboard accessibility and cycle handling.

### Post B — 10,000-row list

**Hook:** A 10,000-row table doesn't need 10,000 DOM rows.

**Body:** I built a small virtualization demo around fixed row height, an overscanned visible window, a full-height spacer, `translateY()`, `ResizeObserver` and rAF-batched scroll updates. The hardest part was making measured height and visible slicing agree—otherwise you can end up with a huge blank region. This is synthetic demo data, not a production benchmark.

**Link:** https://santhoshvishal.vercel.app/notes/virtualized-10000-rows.html

**Where:** LinkedIn, DEV Community, web performance forums where original project posts are allowed.

### Post C — honest AI interface

**Hook:** Not every impressive AI-looking demo needs a model API—and it shouldn't pretend to be one.

**Body:** My portfolio has a client-side console with curated project facts, deterministic lexical scoring and progressively revealed answers. It looks like an agent interface but intentionally has no embeddings, vector database, live model calls or customer data. I documented what the simulation proves and what a production system would need for retrieval, guardrails and tools.

**Link:** https://santhoshvishal.vercel.app/notes/honest-ai-console.html

**Where:** LinkedIn and DEV Community for AI UX discussions. Clarify simulation vs actual production AI work.

## How to measure real reach

| Metric | Source | Why it matters |
| --- | --- | --- |
| Search impressions, clicks, query terms, top pages | Google Search Console | Are people finding the material? |
| Unique repository visitors, referring sites, clones | GitHub **Insights → Traffic** | Are people exploring the source? |
| Build availability, production errors, performance | Vercel deployment / observability | Is the experience reliable? |
| Article visitors and outbound GitHub clicks (optional) | Privacy-conscious first-party web analytics | Which technical lessons bring the right audience? |
| Qualitative technical questions and collaboration messages | Public comments / email | Is reach becoming meaningful? |

Do not add invasive visitor tracking, session replay, fingerprinting, third-party advertising pixels or a cookie banner just to chase vanity metrics. Add analytics only with a deliberate privacy review.

## Launch quality guardrails

- Links must resolve and share previews must not expose private contact data.
- Every published performance claim needs a reproducible baseline and method.
- Respect company/customer confidentiality. Do not repost proprietary UI/screenshots without approval.
- The local AI console is a simulation, not actual provider inference.
- Use real screenshots and short clips only when you have rights to share them.
- Keep the résumé and Contact page accessible, and all first-party pages with a single consistent canonical URL.
